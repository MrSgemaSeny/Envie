## Направление

Референс: **Vercel / shadcn dark**. Тёмная тема, mono-accent — единственный
"акцентный цвет" это сам контраст чёрный/белый, без дополнительного hue.
Цвет (красный) зарезервирован ИСКЛЮЧИТЕЛЬНО под destructive-состояния
(ошибки, подтверждение удаления) — больше нигде не используется, иначе
теряет сигнальную ценность.

Сейчас в проекте UI — голые браузерные дефолты (системный шрифт, подчёркнутые
синие ссылки, серые input-рамки без стилизации, самодельный div для ошибок
бэкенда поверх страницы). Всё это заменяется на систему ниже, начиная со
скелета (Фаза 2), не отдельным проходом в конце.

## Токены (Tailwind v4, `@theme` в `frontend/src/index.css`)

Проект без отдельного Tailwind config-файла — все токены объявляются как
CSS-переменные прямо в `@theme`:

```css
@theme {
  --color-background: #09090b;        /* zinc-950, фон страницы */
  --color-foreground: #fafafa;        /* zinc-50, основной текст */
  --color-card: #18181b;              /* zinc-900, карточки/панели */
  --color-card-foreground: #fafafa;
  --color-border: #27272a;            /* zinc-800 */
  --color-input: #27272a;
  --color-muted: #27272a;
  --color-muted-foreground: #a1a1aa;  /* zinc-400, вторичный текст */
  --color-primary: #fafafa;           /* белая кнопка */
  --color-primary-foreground: #09090b;/* чёрный текст на белой кнопке */
  --color-destructive: #ef4444;       /* ТОЛЬКО ошибки/удаление */
  --color-destructive-foreground: #fafafa;
  --radius: 0.5rem;                   /* единый radius во всём проекте */
}
```

Использование в компонентах — только через эти токены (`bg-background
text-foreground`, `bg-card border border-border`, `bg-primary
text-primary-foreground` для основной кнопки, `text-muted-foreground` для
второстепенного текста). Хардкод-хексы в компонентах — запрещены.

## Типографика

- **Geist Sans** — интерфейс, весь текст по умолчанию.
- **Geist Mono** — числа, даты, код, id.
  `npm install geist` (тот же автор экосистемы, что и компоненты ниже —
  визуально сочетается без дополнительной подгонки).
- Один вес по умолчанию (400/500). 600 — только для заголовков карточек
  и заголовков страниц. Не плодить лишние жирности.

## Обязательные готовые компоненты (не писать свои аналоги)

- **Sonner** (`npm install sonner`) — вся система уведомлений. Заменяет
  текущий самодельный "Backend Status" div поверх страницы. `<Toaster
  theme="dark" />` в корне приложения, `toast.error(...)` / `toast.success(...)`
  вместо ручных div-ов.
- **Vaul** (`npm install vaul`) — все модалки создания/редактирования
  (createTask, createNote, createIdea, generateArchitecture confirm,
  delete confirm). Mobile-first, drag-to-dismiss из коробки, не пишется
  руками с нуля.

## Правила анимации

Источник — методология Emil Kowalski (design engineer, Linear, ex-Vercel,
автор Sonner и Vaul выше, animations.dev). Не общие пожелания "сделай
плавно", а конкретные, проверяемые правила:

- Анимации интерфейса — **не дольше 300ms**. Дольше — только с explicit
  обоснованием, иначе это ошибка, а не стиль.
- Анимировать **только `transform` и `opacity`**. Никогда `width`, `height`,
  `top`, `left`, `margin`, `padding` — это layout-thrashing, дёргается на
  слабом железе.
- **Никогда `linear` easing** для UI-элементов (linear — только для progress
  bar и бесконечных looping-анимаций). Вход — `ease-out`, выход — `ease-in`,
  drag/spring-взаимодействия (Vaul) — пружина, не кривая Безье вручную.
- Поповеры/дропдауны/тултипы масштабируются от `transform-origin` триггера,
  не от центра экрана. Модалки (через Vaul) — исключение, центрируются или
  выезжают снизу.
- Никогда не стартуй анимацию с `scale(0)` — старт с `scale(0.9–0.97)` +
  `opacity: 0`.
- Toast/toggle/drag-анимации обязаны быть **прерываемыми** — ретаргет от
  текущего состояния при повторном срабатывании, не restart с нуля. В
  Sonner и Vaul это уже встроено, руками не переписывать.
- Disabled-элементы не анимируются на hover — не подавай ложный сигнал
  кликабельности там, где кликнуть нельзя.

## Модуль-специфичные визуальные заметки

- **Notes** — карточка поста в стиле твиттера/инстаграм-ленты: аватар не
  нужен (один пользователь), акцент на тексте + превью медиа, теги —
  мелким текстом, приглушённым цветом (`text-muted-foreground`), не
  акцентным.
- **Board** — на самой доске карточки-превью компактные (заголовок +
  прогресс-бар подзадач), без чекбоксов. Полный список подзадач с
  чекбоксами — только на `TaskDetailPage`, куда ведёт клик по карточке.
- **Ideas** — статус идеи (RAW/EXPLORING/ACCEPTED/REJECTED) — как
  маленький бейдж, не как основной цветовой акцент карточки.
- **Wallpaper** — единственное место, где допустим полноэкранный медиаконтент
  без карточной рамки — сама суть модуля в том, чтобы обои показывались
  "как есть", как в Wallpaper Engine.
